# 县域农贸批发冷库入库质检分拣出库结算平台

面向县域农贸批发市场冷库的全流程平台：把**到货登记 → 质检验收 → 分拣 → 库位/保鲜温区 → 出库 → 损耗/投诉 → 账单结算 → 监管追溯**连成一条批次链，
覆盖葡萄、草莓、叶菜、鲜肉、冻品、水产等品类，并把冷库真实经营压力（农户预付款、批发客户锁价、分拣工时、低温仓位、温区故障、降级/转仓/报损引发账单变化）写进流程。

技术栈：Vue 3 + Vite（管理端）、Spring Boot 3 + Spring Data JPA、PostgreSQL（本地/测试默认 H2，免安装即可运行）。

## 一、一键启动（Docker Compose，含 PostgreSQL）

```bash
docker compose up --build
```

- 管理端： http://localhost:8081
- 后端 API： http://localhost:8080
- PostgreSQL：localhost:5432（库 coldchain / 用户 coldchain / 密码 coldchain123）

首次启动自动建表并写入演示主数据（6 个品类、3 个货主、3 个客户、4 个温区、2 张锁价单）和测试账号。

## 二、本地开发（无需 Docker / PostgreSQL）

cd backend

## 三、核心业务与批次链

1. **到货登记**：货主、品类、批次号、产地、重量（原重）、到货温度（自动按品类限值判定超标）、包装、检疫证、预计客户、结算方式（实际可售重量 / 按原重），可标记**混批混装**。
2. **质检验收**：外观、成熟度、腐损率、含水率、测温、票证六维打分，结论为**入库 / 降级入库 / 转分拣 / 退货**（支持部分接受），定级 A/B/C。
3. **分拣**：A/B/C 分级产出、自动算损耗与损耗率、登记**分拣工时**、可标记**分拣损耗争议**与责任方；产出自动分配到品类对应保鲜温区。
4. **库位与温区**：按「批次×等级」落位，记录库位、温区、重量、仓储费起算日；温区可上报故障（自动写入所有在库批次链），支持**转仓**（新库位仓储费自转仓日起算）。
5. **报损**：在仓坏果/超期/故障报损，认定货主/冷库/承运责任，实时扣减可售重量。
6. **出库**：FIFO 扣库位；定价顺序「指定锁价 ＞ 客户有效锁价 ＞ 品类分级参考价」；支持**客户催货优先出库、临时改客户、批发/加工渠道**。
7. **出库后投诉坏果**：按坏果重量与出库单价计赔付，责任归属决定是否冲减货主货款。
8. **结算账单**：
   - 按实际可售重量：实际出库成交额（含锁价）+ 在库余货参考价估值；
   - 按到货原重：原重 × 初评等级价，单独扣回退货与**货主责任**损耗（冷库/承运责任不扣货主）；
   - 统一扣**仓储费（按库位分段，含转仓前后）、分拣费（按吨+工时）、投诉赔付**，并抵扣**农户预付款**；
   - 任何一次降级、转仓、报损、投诉后重新生成账单都会体现变化；结算后批次关账。
9. **监管追溯**：每一步都写入 `trace_event` 批次链（有序号），批次详情页时间线可查看从入库到最终客户（含加工渠道）的完整流向。
10. **调度看板**：每批在仓停留天数、剩余货架期、温区占用与故障、客户催货、锁价标记、损耗率与责任、可售重量变化；按「高风险 › 优先催货 › 已锁价 › 停留天数」排序，给出“先出高风险批次 / 先满足已锁价客户 / 转加工渠道减损 / 立即转仓”建议。

### 手工验证建议（页面操作路径）

1. `docker compose up --build` 后用 admin/admin123 登录 http://localhost:8081。
2. 「到货登记」登记一车草莓并把温度填到 9℃、勾选混批混装 → 自动跳到批次作业。
3. 质检选「转分拣」→ 分拣填 A/B/C 产出并勾选损耗争议 → 看板可见批次落冰温库。
4. 「基础数据」把冰温库上报故障 → 回批次「转仓」→ 对部分 B 级「报损」（选冷库责任）。
5. 「临时改客户」改为城东鲜果连锁，出库时勾选优先+改客户，验证带出锁价 28 元；再登记一笔出库后投诉。
6. 生成账单 → 「结算账单」核对仓储费/分拣费/损耗/投诉/预付款明细后关账。
7. 批次页时间线可从到货一路追到最终客户；看板可见高风险标记与调度建议。
